Garden usability review

Garden can support small text-processing programs with clear value-based state,
readable tests and useful static diagnostics. The largest obstacles in these
exercises were unexpected evaluation rules, failures escaping the interpreter,
and gaps between text, bytes, characters and numeric APIs. The review records
29 improvement candidates rather than treating every rejected syntax as a bug.

All six projects run. JSON is an explicitly incomplete subset; Brainfuck exposes
a byte-list API; the fractal renders ASCII. Those limits are documented with
the corresponding project below. Program completion was secondary to finding
language-design and tooling problems.

Highest-priority areas to consider

- Interpreter robustness: empty-separator hangs (01/02), arithmetic panics
  (03/20) and the incorrect remainder error (21).
- Silent surprises: closure writes (04), equal operator precedence (07), eager
  boolean operands (19), and ignored error/update values (06/23).
- Usable parser/numeric APIs: character construction (09), text/bytes (28),
  Float parsing/order/math (08/13/27), and callback inference (18).

Method: act as a beginner, protocol programmer, library author, systems
programmer, scientific programmer and data-processing programmer. Write and run
small programs, retain failed first attempts as probes, inspect the available
prelude APIs, and distinguish bugs from deliberate semantics or API requests.
Reproductions live in probes/; evidence/probes.json contains source, exit status,
stdout and stderr for both check and run. Nonterminating probes have a three-
second limit. evidence/projects.json records exercise checks, tests and demos.
No performance measurements or editor/LSP session were part of this review.

Environment: Garden 0.26.0, source baseline 7beda2a86cec0e9ede3a480ced14748c7b4ddd50,
rustc 1.95.0, debug build, Linux. Exercise commits change no language source.

Project experiences

HTTP field parser (protocol programmer)

Working: ordered duplicate-preserving header list, colon splitting, ASCII name
validation, case normalization, explicit tab/space trimming, malformed-line
errors. This is a field-section exercise, not an HTTP message parser: no request
line, body framing, or byte-level control-character validation.

Good: split_once returns a destructurable Option tuple; chars and substring
agree on character offsets; enums and structural equality make tests readable.
The type checker caught a missing pair of parentheses in an expression combining
comparison and subtraction. That prevented wrong execution, but the diagnostic
only describes Int/Bool mismatches, not the unexpected grouping.

Hangman (beginner making a console game)

Working: deterministic walkthrough plus --play interactive mode with a random
word; six-miss loss, repeated-letter validation, case normalization and win
handling. State transitions return Result<Game, String>, tested independently
from the console. Scope is deliberately ASCII English words.

Good: plain top-level expressions, tiny test blocks, structural equality and
returned immutable state make this approachable. Explicit Result matches make
all console failure paths visible. Rebuilding a Game for each guess is verbose
but easy to reason about. No special entry-point ceremony was needed.

Brainfuck (systems programmer)

Working: bracket prepass, nested loops, bounded tape, wrapping 8-bit cells,
byte input/output lists, EOF-as-zero and an instruction budget. The demo emits
[65]. Tests cover nested/skipped loops, wraparound, EOF, invalid brackets,
pointer bounds and nontermination. This is an interpreter API, not a terminal
character-output frontend.

Good: Euclidean modulo makes cell wrapping natural; Option bounds checks and
Result allow controlled errors instead of interpreter exceptions. Poor fit:
list replacement needs slice/append/concat, integer jump addresses need string
keys in Dict, and bytes cannot be directly decoded into a String.

JSON parser (library author)

Working subset: recursive arrays/objects, null/bools, exact numeric lexemes
including decimal/exponent grammar, decoded common string escapes, Unicode
literal text, trailing-input validation and a depth limit. Repeated object keys
are preserved. Tests cover nested data and malformed inputs.

Limits: explicitly rejects JSON \u, \b and \f escapes; it only rejects raw tab,
CR and LF among control characters, so this is not a conforming JSON parser.
Numeric lexemes avoid overflow/precision loss, but application code still lacks
a standard decimal conversion. No performance claims: repeated substring calls
rescan character offsets, so this style is unsuitable for large inputs.

Good: recursive enum variants and tuple destructuring make a compact syntax
tree possible. Forward references work. Bad: propagating Result requires
repeated Err(e) => return Err(e) arms; no nested enum patterns or ? shorthand.
Without ordinal/character conversion, standards-compliant string decoding
becomes a much larger project than the recursive grammar.

Mandelbrot (scientific programmer)

Working: ASCII 64 by 25 Mandelbrot escape-time render, tests for known points,
image dimensions and symmetry. Floating point arithmetic uses +., -., *. and
/.. To test squared magnitude < 4, the implementation compares floor(magnitude)
with integer 4. This is equivalent for the nonnegative bounded values used in
this renderer, but a workaround users should not need. render assumes width
and height greater than 1 and a positive iteration limit.

Good: explicit Int.as_float and Float.floor conversions, simple loops and
text output suffice to get a recognizable image. The arithmetic error for +
is unusually helpful. In contrast, float comparisons are impossible with
ordinary operators; <. is not syntax either. There is no sqrt/log/trigonometry
API in the prelude for smooth coloring or common other fractals.

CSV parser (data-processing programmer)

Working: explicit four-state parser for comma-separated rows, quoted commas,
quoted multiline fields, doubled quotes, CRLF or LF separators, empty fields,
and precise failures for malformed quoting. It preserves spaces and permits
ragged rows; schema/column-count validation is outside this exercise.

Good: enum state, straightforward loops, exhaustive matches and equality-based
tests were sufficient without framework code. No new language issue was needed
to implement this after learning the preceding constraints. Compared with the
recursive JSON parser, a local state machine is less affected by Result
propagation boilerplate. Character-by-character substring scans still impose
the same likely scaling limitation; this review has not benchmarked it.
Numbered improvement candidates

01. BUG: nonempty_string.split("") never terminates. Probe 02 times out.
    Reject an empty separator or define a terminating character-split behavior.
02. BUG: nonempty_string.replace("", replacement) never terminates. Probe 03.
    This is a separate operation with its own progress loop, not just split's
    diagnostic. Define insertion semantics or reject the argument.
03. BUG: Int += overflow panics in the debug Rust interpreter (exit 101), while
    + wraps. Probes 14/15. Make compound and ordinary arithmetic consistent and
    keep Garden failures within Garden's diagnostic machinery.
04. SEMANTICS/WARNING: assigning a captured variable inside a map callback
    changes a captured copy, leaving the outer value 0 without warning (11).
    Explain capture-by-value in tooling or warn on misleading captured writes.
05. LIBRARY/DOC: String.trim only removes ASCII space, despite documenting
    whitespace. Tabs and newlines survive (01). HTTP needs a local trim_ows.
    Clarify the contract or offer whitespace and explicit-character variants.
06. WARNING: an ignored fs::write_file Err gets no warning; a program prints
    "saved" after an unsuccessful write (13). Consider a discarded-Result check.
07. DESIGN: all binary operators have equal precedence. During the header
    parser, i != lines.len() - 1 grouped as (i != lines.len()) - 1. Even when
    the checker rejects it, the message doesn't explain grouping. Probe 29
    captures arithmetic and mixed comparison. Standard precedence or a warning
    on mixed operators would reduce surprises.
08. LIBRARY: String has as_int but no as_float (06). JSON decimal/exponent
    values cannot use the obvious symmetric conversion. Add checked parsing.
09. LIBRARY: no integer-to-character conversion (07; prelude API inspected).
    Escaped JSON Unicode and Brainfuck character output need a workaround.
10. DESIGN/DIAGNOSTIC: field assignment s.n = 1 gives "Expected an expression
    after this" at n (09). Immutable state is viable, but this deserves an
    explicit message suggesting construction of a replacement struct.
11. LIBRARY/DESIGN: indexed list assignment is unavailable (08), and List has
    no replacement method. Tape algorithms must rebuild a list or use a dict.
    A persistent list set(index, value) would suit the current value semantics.
12. SYNTAX: nested enum patterns Ok(Some(n)) produce seven parser errors (25).
    Nested matches work, but a precise unsupported-pattern message would help;
    supporting nested patterns would make Result/Option-heavy parsers smaller.

13. MISSING OPERATION: Float has no ordering operators, including <. (05/23).
    Arithmetic has useful dedicated operators but a renderer cannot directly
    express radius_squared < 4.0. Add ordering with a clear NaN policy.
14. SYNTAX/DIAGNOSTIC: scientific literals such as 1e-3 are not recognized;
    errors ask for commas/parentheses instead of identifying the numeric
    syntax (20). Common scientific and JSON examples need rewriting.
15. ERGONOMICS: there is no Result propagation shorthand (10). The JSON
    parser repeats match/Err return plumbing at every recursive step. This
    is a design request, not an incorrect rejection of valid Garden syntax.
16. COLLECTION LIMIT: Dict keys must be strings (32). Brainfuck bracket
    addresses require string_repr conversions on every lookup. Integer or
    generic keys would also help graph algorithms and frequency counters.
17. LIBRARY: no generic/comparator sort and no string ordering (21/33;
    prelude exposes only sort_nums). Sorting names or scored records requires
    implementing both a comparison strategy and sorting. A sort_by API is a
    smaller useful step than a general ordering/typeclass framework.
18. TYPE INFERENCE: map(fun(x) { x + 1 }) checks x as Any and rejects it,
    despite the receiver List<Int> and successful execution (39). The same
    expression works when x: Int is written explicitly. Use callback context
    in lambda parameter inference, or suggest the missing annotation.
19. BOOLEAN SEMANTICS: && and || eagerly evaluate both sides (47/49). The
    practical guarded first().or_throw() on an empty list throws (50).
    Short-circuiting would support safe guards; if eagerness is intentional,
    the operators need prominent documentation and tooling feedback.
20. BUG: minimum Int divided by -1 panics in Rust (30), unlike division by
    zero's Garden exception. This is a division overflow case distinct from
    the compound-assignment inconsistency in finding 03.
21. BAD DIAGNOSTIC: minimum Int % -1 says "dividing ... by zero" although
    the divisor is -1 (31). It should return the representable remainder 0
    or accurately describe the unsupported case.
22. CONSOLE API: read_line represents normal EOF with Err("End of input.")
    (35). Console apps cannot distinguish EOF from I/O failure by type;
    Result<Option<String>, ...> would make that distinction explicit.
23. WARNING: discarded immutable append/set return values silently do
    nothing (37/52); no warning even when the original variable is read
    afterward. This is distinct from ignoring a Result error: a mutation-
    looking operation succeeds, but the update is lost. Consider warning
    for unused returned collection values or making names more explicit.
24. PARSER RECOVERY: unsupported tuple access gets a helpful destructuring
    suggestion followed by an unrelated missing-comma error (24). Preserve
    the good first message and reduce cascades after recognized unsupported
    constructs. Nested patterns (12) are another example of this issue.
25. COLLECTION API: Dict lacks len/is_empty (22). Getting its size requires
    creating the full items list and taking len. Add a direct size query.
26. DEBUG REPRESENTATION: string_repr leaves tabs literal (58), unlike
    newline/CR escaping. Tabs make parser diagnostics and expected values
    hard to read and copy reliably. Escape tabs as \t in representations.
27. NUMERIC LIBRARY: no Float.sqrt (54) or transcendental functions in the
    prelude. Escape-time rendering works, but smooth coloring, distances,
    rotations need common math functions.
28. TEXT/BYTE INTEROP: String has no bytes conversion (56), and the API
    inventory has no UTF-8 encode/decode pair. __fs has byte file I/O, but
    protocol and interpreter code cannot bridge it to text without a manual
    encoding implementation or external process. This is separate from a
    single-codepoint constructor (09).
29. BAD RUNTIME DIAGNOSTIC: a duplicate struct field is correctly detected
    by check, but run says Point does not have a field named x, even though
    it does (44). Retain the precise duplicate-field diagnosis at runtime.

These are 29 improvement candidates, including design/library requests as well
as confirmed bugs. Findings 01/02, 03/20 and 09/28 are related but affect different
operations. Even treating each of those pairs as a single area leaves 26 areas;
this review does not count every failing probe as a new issue.

Useful diagnostics and behavior, not counted as problems

Probe 04: Float + error names +. and offers --fix. Probe 16: invalid escape
reports the actual sequence and lists supported escapes. Probe 17: typo offers
the correct in-scope name and --fix. Probe 18: argument error points both to the
call and the prelude parameter declaration. Probe 19: assertion prints actual
and expected lists. Probe 12: exhaustive-match check names the missing variant.
Probe 27: Unicode len/index_of/substring consistently use codepoint positions.

Further useful tooling observations

Unused local variables and unreachable code get specific warnings (40/48).
Unknown methods get spelling suggestions and fixes during check (45), although
run omits the suggestion. Static checking is a separate operation from run:
run can execute code rejected by check (39/41), and warnings make check exit
nonzero (40/48). Users and editor integrations should know that policy.
Counter closures also produce 1, 1 rather than 1, 2 (38/51), confirming finding
04 beyond one map callback. Reversed slices return [] (42); callers need their
own validation if that should signal a programming error. as_int returns None
for both malformed and overflowing input (36), so parsers cannot explain which
occurred. These observations are not additional numbered findings.

Validation

python3 usability/verify.py passes: six static checks, all 11 unit tests, six
runnable demos, six format checks, plus interactive hangman validation,
duplicate-guess, game-over and EOF smoke checks. Its word choice is random;
assertions cover outcomes common to all configured words.

python3 usability/probe.py captured all 58 probes. The deliberately invalid
programs, two timed-out calls and two host panics are expected observations;
this is not a passing regression suite.

cargo fmt --check and cargo clippy pass. Rustfmt emits the existing stable-
toolchain warning about imports_granularity. No implementation changes were
made, and the Rust reftest suite was not rerun. Existing unrelated untracked
workspace files were left alone. See README.txt for exact reproduction commands.

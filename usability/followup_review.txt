Garden usability follow-up

This pass focuses on warnings, quickfixes, documentation and familiar mistakes
from other languages. New numbered findings continue after review.txt's 29.
Sources and check/run results are in evidence/probes.json. Quickfix replays are
in evidence/fixes.json; the audit uses --stdout and leaves source probes intact.

Documentation correction

The && and || operator pages explicitly explain eager evaluation and show
side-effecting examples. Initial finding 19 is a documented design surprise,
not an implementation bug or a missing explanation on those pages. The original
review has been corrected accordingly.

Warnings and fixes

30. BUG: check --fix --stdout panics on b || b || b (84). Check emits three
    duplicate-expression warnings, including two for the same occurrence.
    Applying overlapping deletions uses invalid byte offsets and exits 101.
    Deduplicate diagnostics and edits, and reject/merge conflicting changes
    before applying a batch. This failure happens even in preview mode.
31. FIX WORKFLOW: an unused-literal binding becomes a bare unused literal
    after one --fix invocation (48/87), requiring another check/fix round.
    Keeping an effectful initializer is correct (90), but known pure literals
    could be removed in one step or remaining warnings could be reported.
32. FIX STATUS: --fix exits 0 without diagnostics for syntax errors that it
    cannot fix, including Python def and semicolons (59/66). Output is unchanged
    and still fails check/run. Automation cannot treat successful fixing as
    successful checking. Report remaining diagnostics or document/provide an
    option for a failing exit status when issues remain.
33. WARNING NOISE: the same-literal-return warning triggers for deliberate
    status-code returns after different logging side effects (82). It is true
    that both return 0, but different branches still matter. Consider making
    this a configurable style hint rather than an unavoidable failing check.
34. WARNING GAP: a local's initial value overwritten before any read gets
    no warning (80). The variable name is used, so an unused-variable check
    does not catch the likely mistaken initialization or forgotten branch.
35. WARNING GAP: List.len() >= 0 is accepted silently and always True (81).
    Catch impossible/tautological length comparisons, not just empty-list
    spellings. This is useful for users confusing >= with >.

Migration mistakes

36. DIAGNOSTIC: def/function/fn declarations are treated as expressions or
    variable references, yielding misplaced punctuation or unbound-symbol
    errors (59/64/65). Recognize common declaration prefixes and suggest
    `fun greet(name: String) { ... }` rather than cascading through the body.
37. DIAGNOSTIC: `elif` is an unknown variable (63), and Python `and` reports
    a missing brace at True (109). Suggest `else if` and `&&`, with a reminder
    of eager evaluation where appropriate. A known foreign keyword deserves
    a more actionable message than a generic unbound-symbol diagnostic.
38. DIAGNOSTIC: `let mut x = 1` reports a missing colon before a type hint
    (77). Say Garden bindings can be reassigned without `mut`, rather than
    implying the author should write a type annotation after `mut`.
39. DIAGNOSTIC: `for i in 0..3` suggests tuple destructuring (70). The problem
    is the Rust-style range. Suggest `range(0, 3)` and leave tuple-access
    guidance for actual tuple expressions.
40. DIAGNOSTIC: `if !False` only says unrecognized `!` (72). Point to
    `not(False)`, just as String + already points to ^. Semicolons (66) could
    similarly suggest removal instead of only rejecting the character.
41. DIAGNOSTIC: `items[0]` reports missing comma/parenthesis (69). This is
    distinct from the earlier list-update gap: ordinary reads have a working
    API, `items.get(0)`, and the message could explain its Option result.
42. SILENT MIGRATION TRAP: "Hello ${name}" runs and prints the placeholder
    literally (68), with no warning despite an in-scope name. A conservative
    optional interpolation-lookalike hint could suggest ^ concatenation.
43. TYPE INFERENCE: binding [] then reassigning an append result fails check
    with List<NoValue> versus List<String>, while execution works (98).
    Suggest annotating `let names: List<String> = []`; ideally infer from use.
    This is a separate inference limitation from lambda parameters (18).

Positive controls

`true` gets a precise True suggestion and an effective fix (60). String +
gets a ^ replacement that checks and runs (67). Assignment in a condition is
rejected as Unit rather than accepted as truthy (74). `main` gets an excellent
warning explicitly explaining top-level expressions (91). A newline after
return is caught with both a return-type error and unreachable-code warning
(97). Truthiness is rejected with concrete types (73).

Self-assignment and Unit-binding warnings are specific (79/83). Unused-tuple
and final-return fixes preserve results (86/88). Removing an unused binding
preserves its print side effect (90); this is an important successful case,
not a reason to remove initializers indiscriminately. Grouped duplicate boolean
operands are fixed correctly in the smaller non-overlapping example (85).

Documentation coverage and library contracts

Reflection finds documentation for all 53 public methods and all 47 public
functions across the prelude, fs, random, reflect, shell and time namespaces.
41 methods and 29 functions contain fenced examples. Fourteen of 15 reflected
types have doc comments; Tuple's documentation is instead in website/type:Tuple.md,
so its absence from reflection is not evidence of missing website documentation.
Doc presence is strong; execution coverage and precise edge-case contracts need
more attention. The inventory counts fences, not assertion quality.

44. DOC VALIDATION BUG: run-code-blocks skips title-only fences used by the
    keyword pages. fun and let report zero checked blocks. A title-only fence
    containing assert(False) passes; `garden title:Example` fails as expected.
    Align the checker with the website's code-fence convention, and report
    skipped Garden-looking examples. evidence/doc_examples.json captures both.
45. DOC VALIDATION GAP: a fenced `test incorrect { assert(False) }` is counted
    as a checked block and passes without executing the test. The fun page's
    embedded test therefore has no effect even if its fence is recognized.
    Execute contained tests or distinguish loaded examples from tested ones.
46. PATH BUG: extension() returns Some("README") for a filename with no dot
    (92), contradicting the contract requiring a dot. Dotfiles and trailing
    dots also need an explicit policy/examples.
47. PATH BUG/DOC: parent() on /file returns Some(Path{ p: "" }), losing the
    root (93). The doc prose says parent always returns a Path and root is
    returned as-is, but its signature/example/runtime return None for root.
    Correct the absolute single-component result and contradictory prose.
48. PATH CONTRACT: joining "" with "file" produces absolute /file; joining
    /tmp with /etc/config yields /tmp//etc/config (94). The one-line doc
    "Append component" leaves empty-base and absolute-component behavior
    unspecified. Preserve relative paths and define absolute-argument handling.
49. NUMERIC CONTRACT: division truncates toward zero but modulo is Euclidean:
    -4 / 3 is -1 and -4 % 3 is 2, so (a / b) * b + (a % b) != a (96).
    `%` documents Euclidean behavior; the division page doesn't explain the
    incompatible quotient convention. Document the pair or provide div_euclid.
50. COLLECTION API GAPS: no fold, reverse or zip (101/103/104), forcing loops
    and indexing boilerplate in ordinary aggregate/pairwise tasks. This is an
    API request, not a demand for iterator syntax or a claim of impossibility.
51. RESULT API GAP: Result has no map (105); routine success-value adaptation
    needs repeated match arms, separate from early-return propagation (15).
    Option/Result combinators would support concise parser composition.
52. TOKENIZATION API GAP: no split_whitespace (102). Replacing tabs/newlines
    and filtering empty strings works, but every text-processing script must
    choose and implement its own whitespace policy. A documented tokenizer
    would pair well with clarifying trim's existing ASCII-space behavior (05).

Additional observations, not counted as new issues: Dict membership is possible
with get(key).is_some() although contains is absent (106). Shell spawn failure
returns the documented -1 tuple with the OS error (100), and invalid UTF-8 text
reads return Err without panicking (99). set_extension replaces everything
from the first dot and appends a trailing dot for an empty extension (95): the
multi-extension behavior is explicitly documented, so this is a migration
surprise rather than an undocumented implementation error. The fun page says
unannotated parameters accept any type, but its arithmetic example is marked
nocheck; probe 107 demonstrates execution succeeding while checking rejects Any
in arithmetic. That needs a clear explanation of the checker/runtime boundary.

Parser and interpreter robustness

The parser was exercised separately via reftest-ast, then each saved input was
run in a fresh interpreter process. Core dumps were disabled and each process
had a two-second limit. AST stdout is discarded to bound large diagnostic-tree
output. A deterministic corpus additionally truncates seven plausible inputs
at every character: 198 cases, with six panic cases and two hangs. Those eight
observations reduce to three incomplete-input failure shapes, not eight issues.
The saved minimal cases and raw exits/stderr are in robustness/ and
evidence/robustness.json. There is no claim that bounded experiments prove the
absence of other failures.

53. BLOCKER, LEXER PANIC: an unsupported non-ASCII source character, such as
    é in café, a smart quote, or a BOM, is sliced as &s[0..1]. Rust panics on
    an invalid UTF-8 boundary instead of producing a Garden diagnostic.
    Unicode whitespace takes a different one-byte advance path and also
    panics. See unicode_identifier/whitespace/bom/smart_quote.gdn.
54. BLOCKER, PARSER RECOVERY: incomplete `(1,` and
    `match x { Some((a` trigger forward-progress assertions, in different
    tuple/pattern parsing loops. These are normal partial editor states;
    return an incomplete-input diagnostic rather than asserting progress.
55. BLOCKER, PARSER HANG: `enum E { A,` never finishes parsing within the
    two-second bound. This can freeze editing, checking and execution before
    any Garden code runs. Recover or stop at EOF in enum variant parsing.
56. BLOCKER, SYNTAX DEPTH: 2,048 parentheses or 1,024 nested lists abort with
    Rust stack overflow. The files are only a few kilobytes. Apply explicit
    nesting limits or iterative parsing/traversal; report a Garden error.
57. BLOCKER, INTERPRETER STACK: `for x in [1] {
    println(string_repr((x, continue))) }` passes check but run panics because
    the next loop index is a function value. Pending argument values survive
    continue. Unwind intermediate values together with expressions/bindings.
    The saved continue_argument.gdn is a small runtime-stack regression case.
58. ROBUSTNESS: `for x in break { ... }` is rejected by check but run panics
    on an empty binding stack. Even unchecked invalid programs need a Garden
    error rather than a host assertion. See for_break_iterator.gdn.
59. BLOCKER, BUILT-IN TYPE COLLISION: redefining List or Float as a struct
    passes check; calling the retained built-in len/floor method panics while
    indexing the empty argument-position vector in its receiver-type error.
    Reserve built-in type names or isolate namespace-local types, and use
    receiver_pos for receiver errors in zero-argument methods. See spoof_*.
60. INCORRECT EXECUTION: parsed `try { throw("expected") } catch(e) { ... }`
    never runs its catch body. Assertions are not caught either. The evaluator
    has a Try node but propagates errors immediately instead of unwinding to
    a handler. Implement catch behavior or reject the incomplete feature.

The existing arithmetic += and division crashes (03/20) remain reproducible;
-= overflow follows the same compound-operation bug, not a new issue. Invalid
arity produces Garden errors, extreme slice bounds are clamped safely, an
empty function returns Unit, and literal Unicode inside strings works. These
successful controls help distinguish host panics from normal Garden errors.

Type-checker review

Fifty-eight focused cases compare check with run in evidence/type_checker.json.
A runtime failure alone is not a checker bug: an explicit throw, a failed
assertion on input, or executing a program that already failed check may be
expected. The following findings use missing static diagnostics or violations
of explicit type relationships; their files show the complete conditions.

61. BLOCKER, STRUCT TYPE ARGUMENT ERASURE: inferred generic struct literals
    lose all type arguments. Box{ value: "wrong" } is accepted as Box<Int>,
    including in an explicitly annotated binding. Generic field arithmetic
    also passes check before failing at runtime. infer_struct_literal solves
    field variables but returns args: []; subtyping zips argument lists
    without checking equal length, accepting the empty list against any
    instantiation. Preserve solved args and check type-argument arity.
    See generic_struct_bad, generic_struct_annotation_bad, generic_struct_flow
    and wrong_struct_field_read in type_checker/.
62. BLOCKER, METHOD RECEIVER CONSTRAINTS: method inference overwrites a type
    variable solved from the receiver with the argument's type, then validates
    arguments without rechecking the receiver. Thus [1].append("wrong") and
    Dict["n" => 1].set("s", "wrong") pass check as homogeneous String
    containers; reading the original Int fails at runtime. User generic
    methods behave the same even with an annotated Box<Int> receiver.
    Keep receiver constraints during unification, validate conflicts and
    preserve existing collection element metadata. See append_then_read,
    dict_then_read, list_metadata_retag and generic_receiver_bound.
63. BLOCKER, UNSOUND VARIANCE: immutable structs/enums are assumed covariant
    in every parameter, including parameters used as callback arguments.
    Handler<List<NoValue>> is accepted as Handler<List<Int>> although its
    stored function only accepts an empty list. A checked program invokes it
    with [1] and fails an empty-list assertion. Immutability alone does not
    justify covariance through a function's argument position. Infer variance
    from parameter occurrences or use invariance initially. See both
    function_field_variance and function_enum_variance.
64. RUNTIME CONTRACT INCONSISTENCY: ordinary function arguments and annotated
    bindings enforce concrete types, but method arguments, enum payloads,
    reassignment and generic return types can bypass equivalent checks.
    Methods accepting an Int can receive an unused String argument; Text(42)
    constructs a declared String payload; identity<T> can return a String
    for T=Int at runtime. Their static errors are correctly caught, so this
    is not another checker false negative. Choose a coherent checked/unchecked
    execution policy; runtime checks or a mandatory preflight should enforce
    the promised boundary. These cases matter for REPL/live replacement too.

Positive controls: higher-order function variance is checked for direct Fun
arguments; concrete closure/function arguments, enum payloads and incompatible
branch types get useful errors. Match/if/for bindings do not leak scope.
Annotated empty containers, recursive enums, forward references, generic pairs
and nested generic constructors work. Specializing a List method to List<Int>
is explicitly rejected with a useful requirement to use List<T>. The empty-
container inference limitation (43) also applies to Dict, and is not counted
a second time. The same applies to contextual lambda inference (18).
